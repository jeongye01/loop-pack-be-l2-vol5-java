# 낙관적 락 재시도 1회 실험 계획

## 질문과 가설

같은 자원 조건에서 낙관적 충돌을 최대 1회 재시도하면 재시도 2회 실험과 비교해 업무 성공·기술 오류·응답시간이 어떻게 달라지는지 확인한다. 충돌을 모두 없애지는 못해도 부분 차감 없이 롤백되어야 한다.

## 고정 조건

| 항목 | 값 |
| --- | --- |
| 전략 | JPA `@Version` 낙관적 락 |
| 재시도 | 최대 1회, 대기 0ms |
| 애플리케이션 풀 | Hikari 최대 40, 최소 유휴 30, 대기 3초 |
| MySQL | `max_connections=50`, 기본 격리 수준 |
| 부하 | S1, 10·30·100 RPS, 각 60초·3회 |

## 검증

동시성 테스트 4종을 10회 실행하고 실패 assertion을 결과로 기록한다. S1 HTTP 부하에서 성공·품절 거절·낙관적 충돌·기술 오류를 분리하고 전체·성공 TPS, p50/p95/p99, 최종 주문·재고·잔액 정합성을 확인한다. 외부 결제 API는 사용하지 않는다.
