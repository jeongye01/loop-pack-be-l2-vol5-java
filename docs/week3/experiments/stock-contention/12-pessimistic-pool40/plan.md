## 질문과 가설

커넥션 풀과 MySQL 연결 상한을 낮췄을 때 비관적 락이 자원 포화에서 보이는 대기시간·타임아웃·처리량 변화를 확인한다. 동일한 S1 요청에서 락 대기와 커넥션 풀이 병목이 될 수 있다.

## 변경 사항

DB 기본 격리수준(REPEATABLE-READ), 비관적 쓰기 잠금, 재시도 0회를 사용한다. Hikari는 최대 40·최소 유휴 30개, MySQL `max_connections`는 50개로 고정한다. 애플리케이션 풀과 MySQL 관리 연결을 함께 수용하기 위한 여유다.

## 검증 순서

1. 동시성 테스트 4개와 실제 격리수준 확인을 10회 실행한다.
2. S1을 10·30·100 RPS, 각 60초·3회 실행한다.
3. 정상 대기·잠금 대기 타임아웃·커넥션 획득 오류·데드락을 구분하고 DB 정합성을 검증한다.
