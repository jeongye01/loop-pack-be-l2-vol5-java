# 비관적 락·외부 API 지연 실험 계획

## 질문과 가설

외부 결제 API가 300ms 걸리지만 DB 트랜잭션 밖에서 호출될 때, 비관적 잠금의 주문 확정 정합성과 전체 HTTP 응답시간을 측정한다.

## 고정 조건

| 항목 | 값 |
| --- | --- |
| 전략 | JPA `PESSIMISTIC_WRITE` |
| 외부 API | 실험용 fake payment, 요청당 authorize 1회·300ms |
| 호출 위치 | 기존 DB 트랜잭션 밖, 부하 생성기에서 먼저 호출 |
| 애플리케이션 풀 | Hikari 최대 40, 최소 유휴 30, 대기 3초 |
| MySQL | `max_connections=50`, 기본 격리 수준 |
| 부하 | S1, 10·30·100 RPS, 각 60초·3회 |

## 검증

가짜 결제 승인 후 기존 주문 확정 API를 호출한다. 확정 성공이면 승인 예약을 유지하고, 품절·잔액 부족·기술 오류면 취소 API를 호출한다. HTTP 전체 p50·p95·p99, 성공·업무 거절·기술 오류, 결제 승인·취소 수, 최종 주문·재고·잔액 정합성을 기록한다.
