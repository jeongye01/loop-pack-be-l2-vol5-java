# Point·Stock 분리 후 낙관적 락 관리자 경쟁 실험 결과

## 실행 조건

- 실험 기준: Point·Stock을 독립 저장 단위로 분리한 구현
- 전략: JPA @Version, DB 기본 격리 수준(REPEATABLE-READ)
- 재시도: 1회, 간격 0ms
- 풀: Hikari 최대 200·최소 유휴 200, 획득 대기 3,000ms
- 부하: S1, 주문 확정 10·30·100 RPS, 각 60초·3회
- 관리자 요청: 주문 부하 중간에 상품 Air의 이름·가격 수정 1회

## 동시성 통합 테스트

이번 HTTP Run에서는 별도 동시성 통합 테스트를 실행하지 않았다.

## 요약

- 총 9개 Run을 기록했다. 각 부하 단계는 3회씩 실행됐다.
- 10 RPS: 기술 오류 0~2건, 전체 응답 p95 35~40ms, DB 검증 전부 통과.
- 30 RPS: 기술 오류 1~6건, 전체 응답 p95 23~24ms, DB 검증 전부 통과.
- 100 RPS: 기술 오류 22~96건, 전체 응답 p95 9~14ms, DB 검증 전부 통과.
- 낙관적 충돌이 기술 오류로 기록되었으며 RPS별 발생 건수는 원본 JSON의 errors.optimisticConflict에서 확인할 수 있다.
- 관리자 응답 시간은 전체 HTTP 응답 시간이며 잠금 대기만 별도로 분리한 값이 아니다.
