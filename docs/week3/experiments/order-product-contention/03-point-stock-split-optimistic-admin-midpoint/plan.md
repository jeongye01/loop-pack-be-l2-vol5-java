# Point·Stock 분리 후 주문·관리자 경쟁 실험 계획

## 전략

- Point와 Stock을 User·Product에서 분리한 구현에서 JPA `@Version`으로 주문·상품·포인트·재고 갱신 충돌을 감지한다.
- 충돌 시 새 트랜잭션에서 최대 1회 재시도한다.
- 재시도 간 대기 시간은 0ms다.
- 관리자 상품 수정은 주문 부하 중간에 1회 실행한다.

## 검증

- S1 주문 확정 10 RPS를 60초 실행하고, 중간 시점에 관리자 상품 수정 1건을 보낸다.
- 주문과 관리자 요청을 별도 trace로 기록해 성공·품절·낙관적 충돌과 응답 시간을 비교한다.
- 주문 상태·재고·포인트·결제 결과를 측정 종료 후 전용 DB에서 검증한다.
- 이번 Run은 분리 구현의 기준선이며, 30·100 RPS와 반복 측정은 후속 Run으로 남긴다.
