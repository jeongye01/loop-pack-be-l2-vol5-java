# Point·Stock 분리 후 비관적 락 관리자 경쟁 실험 결과

## 실행 조건

- 실험 기준: Point·Stock을 독립 저장 단위로 분리한 구현
- 전략: JPA PESSIMISTIC_WRITE; 주문→상품→재고→포인트 순서
- 재시도: 없음
- 풀: Hikari 최대 200·최소 유휴 200, 획득 대기 3,000ms
- 부하: S1, 주문 확정 10·30·100 RPS, 각 60초·3회
- 관리자 요청: 주문 부하 중간에 상품 Air의 이름·가격 수정 1회

## 동시성 통합 테스트

이번 HTTP Run에서는 별도 동시성 통합 테스트를 실행하지 않았다.

## 요약

- 총 9개 Run을 기록했다. 각 부하 단계는 3회씩 실행됐다.
- 10 RPS: 기술 오류 0~0건, 전체 응답 p95 28~37ms, DB 검증 전부 통과.
- 30 RPS: 기술 오류 0~0건, 전체 응답 p95 18~20ms, DB 검증 전부 통과.
- 100 RPS: 기술 오류 0~0건, 전체 응답 p95 8~17ms, DB 검증 전부 통과.
- 비관적 락 충돌은 기록되지 않았고 기술 오류는 0건이었다.
- 관리자 응답 시간은 전체 HTTP 응답 시간이며 잠금 대기만 별도로 분리한 값이 아니다.
