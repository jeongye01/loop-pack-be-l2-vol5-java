# Point·Stock 분리 후 비관적 락 실험 계획

## 실행 조건

- JPA `PESSIMISTIC_WRITE`로 주문·상품·재고·포인트 행을 잠근다.
- 주문 확정은 주문 → 상품(상품 ID 오름차순) → 재고 → 포인트 순서로 조회한다.
- 관리자 상품 수정은 상품 행 잠금을 획득한 뒤 이름·가격을 변경한다.
- 주문 부하 중간에 관리자 상품 수정 1건을 실행한다.

## 검증

- 주문 성공·품절 거절·기술 오류를 구분한다.
- 관리자 HTTP 응답 시간과 락 대기 시간을 별도로 기록한다.
- 주문·재고·포인트·결제 결과를 측정 종료 후 전용 DB에서 검증한다.
