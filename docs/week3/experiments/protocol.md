# 동시성 실험 공통 프로토콜

모든 동시성 실험에 적용할 실행 절차·측정 방식·결과 형식을 정의한다.

## 기록 단위


| 단위         | 의미                                         |
| ---------- | ------------------------------------------ |
| Experiment | 검증할 시나리오와 전략                               |
| Version    | 실행한 코드의 Git SHA                            |
| Run        | 한 Version·시스템 스펙·부하 단계에서 수행한 실행 한 번과 집계 결과 |
| Trace      | Run에 속한 HTTP 요청 한 건의 결과                       |




## 실행 환경 기록

Run 시작·종료 시 컴퓨터 상태를 자동 수집해 `environment.json`으로 저장한다.

| 구분 | 기록할 내용 |
| --- | --- |
| 실행 환경 | CPU·메모리 사양, OS·JVM·MySQL 버전, Docker 자원 설정 |
| 시작·종료 상태 | CPU 사용률, 메모리 사용량·스왑, 주요 프로세스 이름과 자원 사용량 |
| 실행 연결 | Run ID, Git SHA, 시작·종료 시각 |
| 실행 중 변화 | CPU·메모리를 주기적으로 수집했다면 시계열과 수집 간격. 미수집이면 명시 |

## Trace 목록과 형식


| Trace 작업 | 호출 경로 | 기록할 입력 | 측정할 결과 |
| --- | --- | --- | --- |
| `order.confirm` | `POST /api/v1/orders/{orderId}/confirm` | `orderId`, `buyerId` | 결과 분류·오류 종류·지연 시간 |
| `point.charge` | `POST /api/v1/points/charge` | `userId`, 충전액 | 결과 분류·오류 종류·지연 시간 |
| `product.changeStock` | `PUT /api-admin/v1/products/{productId}/stock` | `productId`, 설정 수량 | 결과 분류·오류 종류·지연 시간 |
| `brand.delete` | `DELETE /api-admin/v1/brands/{brandId}` | `brandId` | 결과 분류·오류 종류·지연 시간 |


Trace마다 다음 값을 기록한다.

| 필드 | 의미 |
| --- | --- |
| `runId`, `requestId` | Run과 개별 호출 식별 |
| `operation` | 호출한 HTTP API 작업 이름 |
| 작업별 입력 | 위 표에 적은 식별자와 수량·금액 |
| `startNs`, `endNs`, `latencyMs` | 클라이언트 HTTP 호출 직전부터 응답 본문 수신 또는 오류까지. 데이터 준비·요청 시작 전 스케줄 대기는 제외하고 호출 중 연결·서버 대기는 포함 |
| `httpStatus` | HTTP 응답 상태. 응답을 받지 못했다면 비움 |
| `outcome` | 성공 / 업무 거절 / 낙관적 락 충돌 / 그 밖의 기술 오류 |
| `errorCode` | 거절 코드 또는 기술 예외 종류. 성공 시 비움 |

실험에 없는 작업은 실행하지 않되, 작업 이름과 필드 형식은 공통 목록을 따른다. 처리량·지연 시간 분포·최종 DB 상태는 Run에서 집계·검증한다. 현재 예외 처리기는 낙관적 락 충돌을 `INTERNAL_ERROR`로 응답하므로, HTTP Trace에서 충돌을 별도 분류할 방법은 구현 전에 정해야 한다.

## 공통 측정 방식


| 지표     | 계산 기준                                        |
| ------ | -------------------------------------------- |
| 테스트 결과 | 통합 테스트 통과 여부, 결과 분류별 건수, 최종 DB 상태와 불변식 충족 여부 |
| 전체 처리량 | 완료된 전체 요청 수 ÷ 첫 호출 시작부터 마지막 호출 종료까지의 초       |
| 성공 처리량 | 성공한 요청 수 ÷ 같은 측정 구간의 초                       |
| 지연 시간  | 각 호출 직전부터 반환 또는 예외까지의 p50·p95·p99(ms)        |
| 충돌률    | 낙관적 락 충돌로 종료된 요청 수 ÷ 전체 요청 수                 |


- Run별 계획·실제 시작·완료 요청 수와 시작하지 못한 요청 수(`dropped_iterations`)도 기록한다. 시작하지 못한 요청에는 Trace가 없으며 업무 거절로 세지 않는다.

업무 거절과 낙관적 충돌·데드락·잠금 대기 시간 초과·기타 기술 오류를 구분한다. HTTP 500만으로 원인을 판정하지 않고 서버 오류 기록과 연결한다. 사용하지 않는 전략의 지표는 해당 없음으로 기록한다.

정합성이 깨졌거나 기술 오류가 발생한 Run의 성능 수치는 정상 결과와 구분한다. 비교는 같은 시스템 스펙·부하 단계·반복 조건의 Run끼리 한다.

## 결과 저장 형식

실험 결과의 원본은 JSON으로 저장한다. JSON에서 핵심 결과 표를 자동 생성해 `report.md`에 넣고, 관찰·한계·결론은 직접 작성한다. 수치는 JSON에서 관리하며 Markdown 표를 수동으로 수정하지 않는다. 표를 다시 생성할 때 직접 작성한 해석은 보존한다.

```text
{실험 폴더}/
├── plan.md
├── report.md
└── results/
    ├── test-results.json
    └── {runId}/
        ├── result.json
        ├── traces.json
        └── environment.json
```

| 파일 | 내용 |
| --- | --- |
| `report.md` | JSON에서 자동 생성한 테스트 결과·시나리오/부하별 성능 요약 표와 원본 링크, 직접 작성한 관찰·한계·결론 |
| `test-results.json` | Git SHA, 실행 시각·격리 수준, 회차별 테스트 이름·통과·실패·건너뜀·실패 원인과 원본 리포트 경로 |
| `result.json` | Run 식별 정보, 실제 실행 조건, 요청 집계, 성능 지표, 최종 DB 검증 결과와 관련 파일 경로 |
| `traces.json` | Run ID와 개별 HTTP 요청의 Trace 배열 |
| `environment.json` | Run 시작·종료의 실행 환경과 컴퓨터 상태 |

`result.json`은 다음 항목을 담는다.

| 항목 | 기록할 내용 |
| --- | --- |
| `schemaVersion`, `experimentId`, `runId`, `gitSha`, `status` | 형식 버전, 실행 식별 정보, 실행 상태 |
| `startedAt`, `finishedAt`, `config` | 실행 시각, 시나리오·부하 단계·반복 번호·스펙·실제 격리 수준·목표 RPS·시간·초기 재고·데이터 파일 식별 정보 |
| `requests` | 계획·시작·완료·미시작·미완료 건수, 성공·업무 거절·낙관적 충돌·기술 오류 건수와 오류별 집계 |
| `metrics` | 실제 측정 시간, 전체·성공 처리량, 전체 및 결과 종류별 p50·p95·p99(ms), 충돌률, 품절 전후 집계 |
| `validation` | 검증 상태, 검사별 기대값·실제값·통과 여부와 실패 내용 |
| `artifacts` | Trace·환경 스냅샷·원본 리포트의 상대 경로 |

미측정 값과 해당 없는 지표는 `null`로 기록하고 사유를 남긴다. 미실행 검증은 통과로 기록하지 않는다. 실패·중단된 Run도 상태와 수집한 결과를 저장한다.

결과 수집과 Markdown 표 생성 코드는 아직 구현하지 않았다. 실행 결과가 생기면 위 구조로 저장한다.
