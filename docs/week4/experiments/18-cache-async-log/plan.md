# 실험 로그 비동기화 비교

- 상태: 완료 — 전수 로그 보존, p99 SLO 미달
- 캐시 최신순·무브랜드·첫 페이지 20개·사용자 1. 같은 서울 EC2 부하기·사설 경로.
- 실험 상세 로그를 AsyncAppender 큐로 전송. JSON 생성·필드·출력 형식·SQL/단계 계측은 유지한다. 다른 로거는 변경하지 않는다.
- 큐 8,192건, 폐기 비활성, 포화 시 대기. 정상 종료 flush 최대 30초, Docker 종료 유예 75초. 강제 종료·장애 시 영구 보존을 보장하지 않는다.
- 300→700 RPS 각 30초 준비 후 1,700 RPS·VU 3,000·60초·timeout 5초 1회. 사용자가 요청한 짧은 예열이며 엄격한 안정화 반복 없음.
- 클라이언트 응답 지연·오류·미시작, 서버 Trace 연결·중복/누락, Tomcat busy/current/max, 로그 큐 크기·용량·남은 자리, 자원 상태를 비교한다.
- 큐가 0인지 회복 확인하고 로그 stream을 10초 더 수집한다. 큐 0은 worker 배치 저장 완료와 다르므로 최종 요청 ID 전수 검증은 유지한다.
- 비교 자료: 15번 동기 로그, 16번 동기+덤프, 17번 출력 OFF. 예열·덤프 조건 차이를 표시하고 단일 측정 배율을 일반화하지 않는다.
- 목표 p99 ≤ 200ms·시작 요청 성공률 100%·미시작/미완료 0건. 계측 로그 누락 없이 결과를 확인한다.
