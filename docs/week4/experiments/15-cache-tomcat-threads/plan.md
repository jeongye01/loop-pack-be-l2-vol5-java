# 캐시 hit 부하 중 Tomcat 스레드 포화 확인

- 상태: 완료 — 1회 측정, Tomcat 워커 포화 확인
- 캐시 이미지 `commerce-api:week4-cache-a6ba327`, Tomcat MBean 지표 활성화만 추가. 스레드 설정·앱 로직 동일.
- 서울 EC2 부하기 → 앱 사설 IP, 최신순·무브랜드·첫 페이지 20개·사용자 1.
- 사용자 지시에 따라 300 → 700 RPS 각 30초 짧게 예열한 뒤, 1,700 RPS·VU 3,000·60초·timeout 5초 **1회**만 측정. 엄격한 안정화 반복 없음.
- 공통 5초 자원 표본에 Tomcat busy/current/max를 connector별로 기록. 8080의 busy가 max에 도달하는지 확인한다. 표본으로 순간 포화를 배제할 수 없으며 큐 길이·덤프는 이번 수집 대상이 아니다.
- 고정 데이터·Redis hit, 실행마다 TTL 600초 갱신. 응답·수집 검증과 회복 확인 유지. 전체 집계는 부하 종료 후 수행.
- p99 ≤ 200ms, 성공률 100%, 미시작/미완료 0건과 비교. 종료 후 캐시 배포 상태 유지.
