# 구매 15건/초 확인

읽기 1,700 RPS/VU 3,000, 좋아요 등록·취소 합계 목표 10 RPS/VU 100, 최신순 첫 페이지 TTL 5초를 유지한다. 구매만 15건/초(VU 100)로 낮춰 60초 × 2회 측정한다. 구매는 생성→확정이므로 API 쓰기 약 30 RPS다.

목표: 읽기 p99 ≤100ms, 구매 전체 p99 ≤300ms, 성공률 100%, 미시작 0. 좋아요는 지연을 기록하고 별도 지연 목표는 두지 않는다. 같은 실행 중인 JVM에서 추가 예열 없이 preflight·회복을 확인한다. 이전 실험과 JVM 실행 시점·예열 상태 차이는 남는다.

기존 공통 부하·수집·구매/좋아요 DB 대조를 재사용한다. 통과해도 2회 모두 실행하도록 공통 드라이버에 --repeat-passing 옵션만 추가한다. 앱·API 계약은 변경하지 않는다. 신규 사용자는 회차별 별도 준비하고 seed 전체 응답 일치 검사는 생략한다. 10/20건 결과와 함께 비교하되 두 번 통과만으로 최대 처리량을 확정하지 않는다.
