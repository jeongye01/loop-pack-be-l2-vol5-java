# 캐시 부하 중 Tomcat 스레드 덤프

- 상태: 완료 — 덤프 3회, 실험 로그 락 경합 확인
- 같은 캐시 앱·서울 EC2 부하기·최신순 무브랜드 첫 페이지 20개.
- 앱 재시작 없이 700 RPS 30초 예열 후 1,700 RPS·VU 3,000·60초·timeout 5초 1회.
- 약 15·30·45초에 JVM(PID 1)에 SIGQUIT 전달. JVM은 종료하지 않고 스레드 덤프를 표준 출력으로 남긴다. 공통 Docker 로그 수집에서 덤프를 추출한다.
- Tomcat 8080 워커의 상태·스택과 공통 busy/current/max를 비교한다. 스냅샷이므로 전체 실행 이력이나 정확한 누적 대기 시간으로 해석하지 않는다.
- 덤프 출력 자체가 일시 지연을 만들 수 있는 진단 실행이다. 성능 개선 비교로 쓰지 않는다. 종료 후 회복 확인, 캐시 배포 유지.
