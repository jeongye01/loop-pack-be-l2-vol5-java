# Revision 일괄 조회 — 캐시 OFF / ON 비교

커밋 `81d2933`, 동일 JAR·seed·최신순 첫 20개. 각 조건 앱 재시작 → 300 RPS 20초 → 1,700 RPS 60초, VU 3,000·timeout 5초. 별도 EC2 부하기, 상세 Trace 1%.

**OFF·ON 모두 p99 ≤ 200ms·성공률 100%·미시작 0 SLO 미달.** ON에서 실패는 크게 줄었으나 목표 요청량을 전달하지 못했다. 예열 안정화 없이 진행한 각 1회의 탐색 결과다.

| 항목 | OFF | ON |
| --- | ---: | ---: |
| 시작·완료 | 38194 | 57244 |
| 성공 | 3134 | 57235 |
| 성공률 | 8.2055% | 99.9843% |
| timeout | 35060 | 9 |
| 미시작 | 63807 | 44757 |
| 평균 ms | 4805.95 | 3144.05 |
| p99 ms | 5002 | 4239 |
| 실제 HTTP RPS (drain 포함) | 587.58 | 913.99 |

각 목표 102,000건. 시작+미시작 102,001건은 k6 실행 경계의 실제 집계값이다. 미완료·응답 불일치·본 측정 HTTP/전송 오류 0, 실패는 모두 timeout. 원본 수집 및 회복은 양쪽 모두 성공했다. 실행 스크립트 exit 1은 SLO 관련 미달로 추가 단계를 중단한 것이며 수집 실패가 아니다.

## 관측

| 지표 | OFF | ON |
| --- | ---: | ---: |
| 표본 요청당 SQL | 7회 (391건) | 2회 (547건) |
| 표본 커넥션 대기 평균 | 291.43ms | 191.10ms |
| Hikari active 최대 / pending 최대 | 40 / 167 | 40 / 164 |
| 앱 CPU 평균 (1코어=100%, 2코어) | 185.02% | 183.77% |
| MySQL CPU 평균 (합산) | 125.42% | 48.76% |
| JVM 누적 compilation time 증가 | 80,553ms | 68,386ms |
| GC pause 증가 | 1.512초 | 0.716초 |

두 조건 모두 앱 CPU·Tomcat 워커 200개·Hikari 40개 포화. 로그 큐는 표본에서 0. ON SQL은 인증 1회+revision 일괄 조회 1회이며 원본 상품/좋아요/재고 SQL은 표본에서 없었다. 기존 24번 hit SQL 5회에서 2회로 감소했다. compilation time은 컴파일러 누적 시간이며 CPU 사용량 자체가 아니다. 안정화되지 않은 JVM 상태도 결과에 섞여 있어 개선의 인과 효과를 이 단일 비교만으로 확정하지 않는다.

ON 본 측정 동안 Redis hit +171,741, miss·expired·evicted 증가 0. get 오류는 4→4로 증가 없음. 대상 3키 TTL은 전 232~269초, 후 146~182초. 이번은 만료 스탬피드가 아니라 hit 중심 과부하 실험이다. OFF는 hit/miss 증가 0으로 우회 확인.

## 예열과 과거 기록

OFF 예열 6,001건 중 timeout 5,581·HTTP 오류 71. ON 예열 6,001건 중 timeout 1, p99 3,488ms. 양쪽 모두 회복 확인 후 사용자의 짧은 예열 후 진행 지시에 따라 본 측정했다. 예열 완료를 안정화 성공으로 해석하지 않는다.

- [14번 예전 OFF](../14-no-cache-ec2-video/report.md): p99 5,006ms, 성공률 7.96%, 미시작 63,341건. 이번 OFF와 결과가 비슷하나 당시 SQL 5회·로깅·예열이 다르므로 동일 병목이라고 단정하지 않는다.
- [19번 예전 ON](../19-cache-sampled-log/report.md): p99 51/73/30ms, 모두 성공·미시작 0. 단일 완성 응답 캐시, 인증 SQL 1회, DB revision 없음. 현재는 캐시 3개·조합·revision·트랜잭션 범위가 달라 직접적인 동일 구현 비교가 아니다.
- [24번 개선 전 ON](../24-combined-product-slo/report.md): p99 5,001ms, 성공률 91.67%, 미시작 58,036건. 이번에는 SQL 중복만 줄였으며 Redis 순차 3회와 읽기 트랜잭션 범위는 유지했다.
