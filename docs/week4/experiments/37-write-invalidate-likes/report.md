# 읽기·구매·좋아요 혼합 부하 3회

36번과 같은 Write Invalidate 빌드에 좋아요 등록·취소 합계 목표 10 RPS만 추가했다. 읽기 1,700 RPS, 구매 10건/초, 좋아요 등록→취소 흐름 5건/초를 60초씩 3회 실행했다. 최신순 첫 페이지 TTL 5초, 나머지 300±30초, 로컬 Single Flight 유지.

사용자가 측정 중 확정한 목표는 읽기 p99 ≤100ms, 구매 전체 p99 ≤300ms, 시작된 요청 성공률 100%, 미시작 0이다. 좋아요 지연은 별도 목표 없이 관찰한다. 원본 slo-runs.json에는 실행 당시 공통 100ms 판정이 남아 있으며 수정하지 않았다. 새 기준의 판정은 revised-slo.json으로 분리했다. 구매는 3회차만 새 목표를 통과하고, 읽기는 모두 초과해 전체 판정은 모두 미달이다. 구매는 주문 생성→확정의 전체 사용자 흐름이다. 좋아요는 등록·취소 API를 각각 잰다. 서로 다른 작업의 지연을 합산한 p99는 아니다.

## 원본·캐시·자원

| 회차 | 목록 원본 / 최대 동시 | 재고 원본 / 최대 동시 | 삭제 성공 / 실패 | 삭제 키 수 | Redis GET 오류 |
| --- | --- | --- | --- | ---: | ---: |
| run-1 | 12 / 1 | 585 / 1 | 1201 / 0 | 586 | 0 |
| run-2 | 13 / 2 | 585 / 2 | 1199 / 1 | 583 | 39 |
| run-3 | 12 / 1 | 592 / 1 | 1202 / 0 | 592 | 0 |

삭제 성공은 삭제 작업 실행 성공이며 반드시 키가 있었다는 뜻은 아니다. 좋아요 쓰기는 해당 사용자의 내 좋아요 캐시만 무효화하고, 이 시나리오는 그 캐시를 미리 채우지 않는다. 좋아요 표시 수와 순위는 기존 TTL 갱신 정책이므로 등록·취소마다 최신순 공통 목록이 무효화되는 실험이 아니다.

| 회차 | Redis key hit / miss | Hikari pending 최대 | Tomcat busy 최대 | 앱 CPU 평균 / 최대 |
| --- | --- | ---: | ---: | --- |
| run-1 | 328,149 / 12,133 | 0 | 91 | 153.16% / 196.07% |
| run-2 | 326,557 / 11,321 | 0 | 63 | 148.26% / 182.78% |
| run-3 | 322,007 / 8,998 | 0 | 71 | 161.92% / 192.84% |

원본 호출은 본 측정 run ID 기준이다. 동시는 DB 풀 대기를 포함하며 동시에 실행 중인 SQL 수가 아니다. Redis·캐시 증분에는 preflight/recovery 등이 포함될 수 있고 key hit/miss는 API 요청 hit율이 아니다. 자원은 5초 표본이다.

## 정합성 대조·비교 범위

구매는 주문·재고·포인트 변화와 실제 성공 응답을 대조했다. 좋아요는 각 흐름의 201 등록→200 취소 기록을 확인하고 신규 사용자들의 DB 좋아요 관계가 모두 없어졌는지 대조했다. 표시 좋아요 수의 신선도, 다른 사용자의 좋아요 목록, 무효화 실패·늦은 채움은 이번 부하의 검증 범위가 아니다. 36번의 정합성 실패 결과가 해결됐다는 뜻도 아니다.

| 회차 | 구매 대조 | 좋아요 대조 | 남은 좋아요 관계 |
| --- | --- | --- | ---: |
| run-1 | 통과 | 통과 | 0 |
| run-2 | 통과 | 통과 | 0 |
| run-3 | 통과 | 통과 | 0 |

36번 읽기 p99는 2,623/229/76ms, 구매 p99는 4,889/425/230ms였다. 이번에는 서버를 재시작하지 않았고 36번의 실행 상태를 이어받은 뒤 최초 읽기 예열을 추가했다. 따라서 회차별 지연 차이 전체를 좋아요 추가 효과로 해석하지 않는다. 동일 JVM 예열 상태를 맞춘 A/B 비교는 아니다.

## 실행·검사 자료

배포본 서버 추적 필터는 목록·주문만 포함하므로 좋아요 내부 trace는 수집되지 않았다. 좋아요 지연과 성공률은 모든 클라이언트 요청을 대상으로 측정했다.

공통 products.js에 선택적 좋아요 시나리오, 공통 집계에 등록·취소 지표와 서버 trace 분리, 좋아요 DB 사후 대조를 추가했다. 앱 코드·API·도메인 계약은 변경하지 않았다. k6 inspect, 부하 프로세스 테스트 4개, 본 측정과 분리된 소량 등록·취소 확인을 통과했다. 앱 테스트·Checkstyle·ArchUnit은 같은 빌드를 그대로 사용하므로 재실행하지 않았다.
