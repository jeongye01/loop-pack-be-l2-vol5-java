# Single Flight + revision OFF — TTL 5초

34번과 동일한 빌드·데이터 구성·부하에서 최신순 첫 페이지 TTL만 2초→5초로 변경한다. 사용자의 최종 선택은 5초이며 15초·20초 조건은 실행하지 않았다.

| 항목 | 설정 |
| --- | --- |
| 읽기 | 최신순 첫 20개, 1,700 RPS, VU 3,000 |
| 구매 | 생성→확정 10건/초, VU 100 |
| 본 측정 | 60초 × 3회, 회차별 신규 구매자 |
| SLO | 읽기·구매 각각 p99 ≤100ms, 성공률 100%, 미시작 0 |
| 조율 | 로컬 Single Flight |
| revision | 읽기·쓰기 OFF, 프로세스별 고정 실험 namespace |
| TTL | 최신순 첫 페이지 5초, 나머지 300±30초 |
| 예열 | 설정 재배포 후 300/700 RPS 각 30초 한 번만, 이후 회복 확인 |

추가 테스트·lint·seed 응답 일치 검사는 사용자 요청대로 생략한다. 기존 JAR을 재사용하며 부하 후 구매 DB 결과 대조와 자원 회복 기록은 유지한다.

revision 무효화가 없는 진단 실험이라 변경 표시 값의 즉시 갱신을 보장하지 않는다. TTL 변경을 위해 앱이 재시작되므로 JVM 예열·시간 경과 효과가 남는다. 읽기·구매 지연, 원본 목록/재고 호출, Redis 오류·hit/miss, Hikari·Tomcat·CPU를 34번과 비교한다. 최초 예열이 읽기 전용이라는 한계도 유지한다.
