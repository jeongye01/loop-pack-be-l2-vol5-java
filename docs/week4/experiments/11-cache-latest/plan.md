# 조회 성능 실험 계획서: 최신순 목록 Redis 캐시

- 실험 ID: 11-cache-latest
- 상태: 3회 완료, 목표 미달
- 작성일: 2026-10-15
- 기준 버전: `b2f1b82`
- 공통 절차·결과 형식: [프로토콜](../protocol.md)
- 장비 사양: [서울 EC2](../environments/ec2-seoul.md)

## 실험 내용

**데이터를 변경하지 않는 조건에서 캐시 적용 전후의 조회 성능을 비교한다.**

- 요청: 최신순·브랜드 필터 없음·첫 페이지 20개, 사용자 1
- 부하: 1,700 RPS·VU 3,000·60초·timeout 5초·3회
- 목표: 클라이언트 p99 ≤ 200ms·성공률 100%·미시작 0건
- 비교: 응답 시간·성공/실패·미시작 요청 수·SQL 수·앱/DB 자원 사용
- 기존 공통 부하 실행·수집 스크립트를 재사용한다.

## 변경 사항

최신순 목록에 Redis 캐시를 붙이고, 캐시를 채운 상태에서 부하를 보낸다.

키: `products:list:v1:sort=latest:brand=all:page=0:size=20`

`v1`은 캐시 응답 구조 버전이다. 실험 전용 스위치로 활성화하고 사용자 확인은 유지한다. 실험 키 TTL은 10분이며 운영 신선도 정책을 뜻하지 않는다. 측정 후 스위치를 끄고 해당 키를 삭제한다. 이번 실험에서는 데이터 변경에 따른 정합성 처리를 다루지 않는다.

## 적용 전 기록

[09번 기준선](../09-load-latest-1700/report.md): p99 5,003~5,005ms, 시작 요청 성공률 45.30~47.59%, 미시작 56,433~57,216건.
