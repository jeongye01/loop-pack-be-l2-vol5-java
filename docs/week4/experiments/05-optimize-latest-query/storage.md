# 최신순 인덱스 용량

**추가 직전 EC2 디스크 사용량은 미수집이다.** 추가를 시작한 뒤 용량 기록 요청을 받았으므로 전후 디스크 증가량을 확정하지 않는다. 인덱스를 삭제해도 InnoDB 테이블 파일이 즉시 줄지 않아 삭제·재생성으로 가짜 기준값을 만들지 않았다.

| 항목 | 추가 전 | 추가 후 |
| --- | ---: | ---: |
| EC2 루트 디스크 사용량 | 미수집 | 6,274,723,840바이트 (약 5.84GiB), `df` 33% |
| 무필터 최신순 인덱스 | 미존재 | 26,804,224바이트 (25.56MiB) |
| 브랜드 최신순 인덱스 | 미존재 | 36,257,792바이트 (34.58MiB) |
| 신규 인덱스 합계 | 0 | 63,062,016바이트 (60.14MiB) |

EC2 루트 디스크 전체는 19,594,608,640바이트, 가용은 13,303,107,584바이트다. 기록 시각 2026-10-14 01:52:20 UTC (10:52:20 KST).

인덱스 크기는 `mysql.innodb_index_stats`의 `size × 16,384바이트`로 계산한 페이지 할당 통계다. 파일시스템 실제 증가량과 같다고 단정하지 않는다. 새 인덱스는 각각 1,636페이지·2,213페이지다. `information_schema.TABLES.INDEX_LENGTH`는 이번 수집에서 개별 인덱스 통계 합계와 일치하지 않아 합계 근거로 사용하지 않았다.

원본: `build/05-optimize-latest-query/storage/after.txt`. 다음 인덱스 실험부터는 DDL 실행 직전·직후 같은 방식으로 디스크와 인덱스 통계를 수집한다.
