# 통합 상품 API 정상 상태 SLO

- 대상: `GET /api/v1/products?sort=latest&page=0&size=20`, 브랜드 필터 없음. 상품·좋아요 수·품절을 한 응답으로 받는다. 프론트 제외.
- 목표: 1,700 RPS, 전체 응답 p99 ≤ 200ms, 성공률 100%, 미시작·미완료 0.
- 실행: 통합 버전 배포·상태/seed 응답 확인 → 300·700 RPS 각 20초 예열 → 1,700 RPS 60초 1회. VU 3,000, timeout 5초. 예열에 오류·미시작이 있으면 증량을 중단하고 결과를 남긴다.
- 기존 별도 부하 EC2 → 앱 사설 IP. 공통 RemoteRunner·products.js 재사용. 전수 요청 로그 없이 k6 지표로 전수 집계, 서버 상세 trace 1% 유지.
- 상품 순서·가격·브랜드·좋아요 수·품절·페이지를 seed와 비교. 불일치 시 중단.
- TTL 5분 ±30초 유지. 세 내부 캐시의 측정 전후 TTL과 캐시 오류·Redis hit/miss/eviction/expiry를 기록한다. 키 삭제·TTL 연장 없이 실행하며 자연 만료가 섞이면 순수 hit으로 부르지 않는다.
- 클라이언트 전체/성공 지연·실제 요청 수·시작/완료/실패/미시작, 앱 CPU·Tomcat·Hikari·Redis/DB/부하기 자원 및 회복을 수집한다. API p99는 클라이언트 요청 직전~응답 수신 완료이며 응답 검증 시간은 제외한다.
- 이번 1회는 현재 상태 확인이다. 반복 안정성·캐시 스탬피드 재현은 별도 실험이며 SLO를 미리 통과한다고 가정하지 않는다.

## 실행 중 사용자 지시

300 RPS 예열 실패 후 사용자가 본 실험 즉시 실행을 요청했다. 실패 기록은 보존하고 회복 확인 후 `--measure-only`로 1,700 RPS·60초 1회 진행한다. 예열 안정화를 확인한 결과로 해석하지 않는다.
