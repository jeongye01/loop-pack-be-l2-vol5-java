# Single Flight + revision OFF — TTL 2초 혼합 부하

읽기 1,700 RPS + 구매 10건/초, 60초 × 3회, 최초 예열만 수행했다. **3회차 읽기만 p99 100ms를 통과했고, 구매는 세 회차 모두 미달했다.**

| 회차 | 읽기 완료 | 구매 완료 | 읽기 평균 / p99 | 구매 평균 / p99 | 미시작 | 시작 요청 성공률 |
| --- | ---: | ---: | --- | --- | ---: | --- |
| run-1 | 96,924 | 601 | 1629.32 / 2534.00ms | 2674.55 / 4611.00ms | 5,077 | 100% |
| run-2 | 102,001 | 601 | 23.13 / 179.00ms | 99.66 / 350.00ms | 0 | 100% |
| run-3 | 102,001 | 600 | 7.61 / 62.00ms | 52.39 / 210.01ms | 0 | 100% |

본 측정 HTTP 오류·timeout·미완료 0건. 구매 DB 결과 대조는 모두 통과했다. 1회차 미시작은 읽기 요청이며 구매는 전부 시작했다. 601건은 계획 600건에 경계 요청 한 건이 포함된 값이다.

| 회차 | 목록 원본 / 최대 동시 | 재고 원본 | Hikari pending 최대 | Tomcat busy 최대 | 생성 p99 / 확정 p99 |
| --- | --- | ---: | ---: | ---: | --- |
| run-1 | 31 / 2 | 0 | 135 | 200 | 2532.00 / 2559.00ms |
| run-2 | 30 / 1 | 0 | 0 | 148 | 175.00 / 233.00ms |
| run-3 | 30 / 1 | 0 | 0 | 29 | 94.24 / 143.05ms |

재고 원본 0은 해당 X-Run-ID 지표 시계열이 생성되지 않은 경우를 포함한다. 인증 DB 조회는 유지했다. 읽기 표본 및 구매 전수 trace에서 revision SELECT/UPDATE는 관측되지 않았다. Single Flight는 유지하며 miss 소유자만 기존 읽기 트랜잭션에 진입한다.

## 해석

로컬 Single Flight + revision ON(32번)의 읽기 p99는 3,064/1,524/841ms, 구매는 5,677/2,897/1,531ms였다. 이번에는 revision SQL뿐 아니라 쓰기에 따른 재고 캐시 무효화까지 없앴다. 따라서 좋아진 수치 전부를 revision SELECT 한 번 제거 효과로 설명하지 않는다. 쓰기 중 표시 값의 즉시 갱신도 보장하지 않는 진단 조건이다.

첫 회차와 후속 회차 차이가 크다. 예열은 읽기 300/700 RPS이므로 구매 경로까지 충분히 예열됐다고 주장할 수 없다. JVM·CPU·런타임 상태 효과도 남는다. 이번 3회만으로 안정적인 100ms SLO 달성을 주장하지 않는다. 32번은 회차마다 예열했고 이번은 최초 한 번만 수행한 절차 차이도 있다.

첫 예열 300 RPS는 timeout 19건·p99 3,742.15ms, 다음 700 RPS는 성공률 100%·p99 30ms였다. 본 측정과 분리 기록했다.

사용자 요청에 따라 추가 테스트·lint 재실행을 생략하고 prepareDocker만 성공 후 배포했다. 부하 결과·주문 대조는 런타임 실험 결과이며 전체 회귀 통과를 대신하지 않는다.
