# 최신순 캐시 — 서울 EC2 부하기 비교

- 상태: 완료 — 3회 측정, p99 SLO 미달
- 비교 대상: [12번 로컬 부하기 실험](../12-cache-latest-warmed/report.md)

## 목적

로컬 PC·인터넷 경로를 서울의 별도 EC2·사설 IP 경로로 바꿔, 클라이언트와 서버 내부 시간 차이가 줄어드는지 확인한다. 부하기 장비와 경로가 함께 바뀌므로 둘 중 하나의 단독 효과로 단정하지 않는다.

## 조건

| 항목 | 값 |
| --- | --- |
| 부하기 | 별도 EC2 · x86_64 · 8 vCPU · 32GiB · 사설 IP 172.31.22.59 |
| 요청 대상 | http://172.31.26.165:8080 · 최신순 · 무브랜드 · 첫 페이지 20개 · 사용자 1 |
| 본 측정 | 1,700 RPS · VU 3,000 · 60초 · timeout 5초 · 3회 |
| 목표 | 클라이언트 p99 ≤ 200ms · 시작 요청 성공률 100% · 미시작/미완료 0건 |
| 캐시·데이터 | 12번과 동일 이미지·고정 데이터·Redis hit · 각 실행 전 TTL 600초 갱신 |

300 → 700 RPS 각 30초 후 1,000 RPS로 준비한다. 연속 두 번 오류/미시작 0건, JIT 증가율 각각 100ms/초 이하, p95 차이 20% 이내·CPU 평균 차이 10%p 이내면 본 측정한다. 최대 8회 안에 안정화되지 않으면 중단한다.

공통 `products.js`의 요청·응답 검증·로그를 그대로 사용한다. 부하기에서 로그를 파일로 기록하고 종료 후 가져온다. 앱/DB/부하기 자원과 요청별 서버 시간을 수집하고 전체 로그 집계는 모든 부하 종료 후 수행한다. 부하기 자원 부족 여부도 함께 확인한다. 제어·회복 확인 요청은 기존 로컬 경로이며 본 측정과 분리한다.

실험 후 캐시를 끄고 기존 앱으로 복구한다. 부하기 EC2 중지는 별도로 진행한다.

k6 버전 표기는 양쪽 v2.3.0이나 빌드는 다르다. 로컬은 darwin/arm64 · commit/devel · Go 1.27.1, 원격은 공식 linux/amd64 · e088784614 · Go 1.26.8이다. 실행 환경 변경에 포함해 기록한다.

사용자 실행 중 지시: 대략 예열되면 본 측정으로 진행하며 추가 준비 반복을 최소화한다. 실제 준비 지표와 기존 안정화 기준 통과 여부는 결과에 그대로 남긴다.
