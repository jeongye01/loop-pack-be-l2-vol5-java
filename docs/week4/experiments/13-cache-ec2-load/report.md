# 서울 EC2 부하기 — 최신순 캐시 결과

**3회 모두 성공률 100%·미시작 0건이지만, p99 200ms 목표는 미달했다. 로컬 PC·인터넷만으로 이전 지연을 설명할 수 없다.**

별도 EC2 8 vCPU/32GiB → 같은 서브넷 앱 사설 IP. 고정 데이터·Redis hit·최신순·무브랜드·첫 페이지 20개, 1,700 RPS·VU 3,000·60초·3회. 앱은 12번과 동일 이미지다.

부하기 전체 CPU·메모리 고갈은 관측되지 않았다. 다만 프로세스 내부 직렬 구간이나 순간 지연까지 배제하는 근거는 아니다. 캐시 miss/fill 증가는 없고 요청당 SQL은 사용자 확인 1회다.

서버 내부 평균은 약 10~11ms인데 클라이언트 평균은 240~751ms다. 다음은 **서버 계측 시작 전 Tomcat 작업 대기, 계측 종료 뒤 로그 출력·응답 전송, 부하기의 응답 대기 구간**을 분리해서 확인한다. 이번 측정만으로 Tomcat이나 로그를 병목으로 확정하지 않는다.

## 실행 기록

300 → 700 RPS 각 30초, 이후 1,000 RPS 4회 준비했다. 사용자 요청으로 추가 예열을 최소화하기로 했고, 당시 실행 중이던 준비가 끝날 때 기존 기준도 통과해 바로 본 측정했다. 마지막 p95 8→9ms, CPU 44.07→44.20%, JIT 증가율 25.04→22.77ms/초, 오류·미시작 0건이었다.
