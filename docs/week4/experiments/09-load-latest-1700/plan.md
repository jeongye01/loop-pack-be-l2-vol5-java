# 조회 성능 실험 계획서: 최신순 1,700 RPS 현황

- 실험 ID: 09-load-latest-1700

- 작성일: 2026-10-15
- 실행 버전: `d0b16cc`, 실제 배포 이미지·설정은 각 Run 환경 기록 참조
- 공통 절차·결과 형식: [프로토콜](../protocol.md)
- 장비 사양: [서울 EC2](../environments/ec2-seoul.md)

## 실험 내용

`GET /api/v1/products?sort=latest&page=0&size=20`, 사용자 1, 브랜드 필터 없음.

**1,700 RPS × 60초 × 3회**, VU 3,000, timeout 5초. 회당 예정 요청 약 102,000건이며 사용자 수와는 다르다. 최초 준비 실행은 1 RPS·30초로 측정에서 제외한다.

목표는 클라이언트 p99 **200ms 이하**, 시작한 요청의 성공률 **100%**, 미시작·미완료 요청 **0건**이다. 오류·timeout·응답 불일치도 모두 실패에 포함한다. 성공률은 성공/시작, 예정 부하 달성 여부는 dropped와 별도로 확인한다.

## 변경 사항

앱·DB·쿼리·캐시 설정을 바꾸지 않고 현재 상태를 측정한다. 기존 1,000 RPS 실험과 같은 VU·timeout·수집 방식을 유지한다. 과부하 오류가 나더라도 회복 확인 후 동일 부하를 3회 반복한다. 응답 불일치 또는 회복 실패 시 남은 실행을 중단한다.

로컬 k6와 공용 네트워크를 사용한다. 실행 중 프론트 수동 조회는 제외한다. 서버 CPU·메모리·디스크 I/O·Hikari 대기와 발생기 자원을 함께 기록한다. VU 부족이나 발생기 제약을 서버 처리량 한계로 단정하지 않는다.
