# 캐시 없는 최신순 — 프론트 촬영 당시 상태

**앱 호스트 CPU 평균 98.6%로 포화됐고, 시작 요청의 92.0%가 5초 timeout이었다.** 메모리·디스크 포화보다 앱 CPU 병목 징후가 두드러진다. CPU를 사용하는 세부 경로는 추가 분석이 필요하다.

서울 별도 EC2 → 앱 사설 IP, Redis 캐시 비활성. 최신순·무브랜드·첫 페이지 20개, 1,700 RPS·VU 3,000·60초·timeout 5초 **1회**. 사용자 프론트 촬영 병행 실행이며 브라우저 추가 요청 수는 계측하지 않았다.

미시작은 서버까지 보내지 못한 요청이며 timeout과 구분한다. k6 실행 경계 때문에 시작+미시작 합계가 목표보다 1건 많으며 원본 수치를 보존했다. 모든 SLO 미달이다.

## 준비·종료

300·500 RPS 각 30초 예열 후 실행했다. 사용자 요청에 따라 추가 안정화 반복 없이 진행했다. 준비 자체도 과부하였으며 300 RPS에서 timeout 7,997건·HTTP 오류 4건, 500 RPS에서 timeout 10,179건이었다. 따라서 안정적인 정상 부하에서 준비됐다고 주장하지 않는다. 각 실행 후 회복 확인은 통과했다.

본 측정 종료 후 부하기 프로세스 종료·앱 회복 확인 완료. 앱은 캐시 없는 기존 이미지 그대로 유지했다. 부하기 EC2는 켜져 있다.
