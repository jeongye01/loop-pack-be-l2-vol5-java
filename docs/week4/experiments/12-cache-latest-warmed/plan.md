# 조회 성능 실험 계획서: 준비 부하 후 최신순 캐시 재측정

- 실험 ID: 12-cache-latest-warmed
- 상태: 완료 — 3회 측정, SLO 미달
- 작성일: 2026-10-15
- 실행 버전: 11번과 동일한 캐시 실험 이미지, 실행기만 수집/집계 분리
- 공통 절차·결과 형식: [프로토콜](../protocol.md)
- 장비 사양: [서울 EC2](../environments/ec2-seoul.md)

## 실험 내용

데이터 변경 없이 최신순·브랜드 없음·첫 페이지 20개·사용자 1을 조회한다. 캐시를 채우고 **300 → 700 RPS 각 30초**, 이후 **1,000 RPS·30초**를 반복한다.

연속 두 번의 1,000 RPS 준비 실행에서 오류·미시작 0건, JIT 누적 시간 증가율 각각 100ms/초 이하, 두 실행의 p95 차이 20% 이내·앱 CPU 평균 차이 10%p 이내면 준비 완료로 본다. 최대 8회까지 안정되지 않으면 본 측정을 시작하지 않는다. 이는 실험 준비 기준이며 서비스 SLO와 구분한다.

준비 후 **1,700 RPS·VU 3,000·60초·timeout 5초·3회** 측정한다. 목표는 클라이언트 p99 ≤ 200ms·성공률 100%·미시작 0건. 회차 사이에는 기존 회복 확인을 유지한다.

## 변경 사항

앱·DB·캐시 구현과 자원 설정은 11번과 같다. 실험 키 만료가 끼지 않도록 각 실행 전 기존 키의 TTL 600초를 갱신하고 기록한다.

공통 실행기에 집계 지연 옵션을 추가한다. 실행 중에는 수집만 하고 준비 판단은 작은 k6 요약·자원 표본으로 수행한다. Trace 연결·전체 분석은 모든 부하 종료 후 실행하며, 프론트 조회·빌드·배포·별도 분석을 겹치지 않는다. 중복 로그·누락 검증은 그대로 유지한다.

측정 후 실험 캐시를 끄고 기존 앱으로 복구한다.
