# 상세 실험 로그 OFF — 출력 병목 비교

**상세 로그 출력만 끄자 평균 응답 23ms, p99 237ms로 내려갔다.** 덤프에서 확인한 동기 로그 출력 락 경합이 부하 성능을 크게 왜곡했다는 근거다. 기존 실험은 서비스 로직 단독 한계가 아닌 동기 상세 계측 로그를 포함한 구성의 성능으로 해석한다.

## 해석 범위

동기 출력 락 경합이 중요 원인이라는 덤프 증거와 OFF 결과가 일치한다. 다만 16번은 덤프 출력이 포함됐고 앱 재시작 없이 예열했다. 이번은 설정 적용을 위해 재시작했고 짧은 예열만 했다. 따라서 표의 차이를 통제된 반복 실험의 정확한 개선 배율로 주장하지 않는다.

이번 700 RPS 예열은 timeout 16,304건·미시작 2,502건으로 정상 부하 준비가 아니었다. 사용자 요청대로 추가 안정화 반복 없이 회복 확인 후 본 측정을 진행했다. 본 측정 초반 busy=200이 한 번 남았으며 워밍업 충분 여부도 후속 확인 대상이다.

## 수집과 검증

상세 로그가 없어서 요청별 서버 시간·SQL 수·DB 획득 대기는 **측정 불가**다. 0ms·0회로 해석하지 않는다. 공통 집계의 `measurementComplete=false`와 `failed`는 서버 Trace가 의도적으로 없어 기존 연결 검증을 통과하지 못했다는 뜻이다. 검증 기준은 완화하지 않았다. 클라이언트 응답 정합성·완료 수와 k6 요약, 자원·Tomcat 수집은 정상이다.
