# 상품 목록 조회 API 계약

## API 계약

### 요청

```http
GET /api/v1/products
X-USER-ID: 1
```


| 항목          | 위치  | 필수  | 기본값      | 조건                                  |
| ----------- | --- | --- | -------- | ----------------------------------- |
| `X-USER-ID` | 헤더  | 예   | 없음       | 존재하는 사용자 ID                         |
| `brandId`   | 쿼리  | 아니오 | 없음       | 지정하면 해당 브랜드의 상품만 조회한다.              |
| `sort`      | 쿼리  | 아니오 | `latest` | `latest`, `price_asc`, `likes_desc` |
| `page`      | 쿼리  | 아니오 | `0`      | 0부터 시작                              |
| `size`      | 쿼리  | 아니오 | `20`     | 1~100                               |


### URL 쿼리 파라미터

```http
GET /api/v1/products?brandId=7&page=0&size=20&sort=price_asc
```

#### 필터링


| 필터  | 파라미터      | 동작                                                 | 예시           |
| --- | --------- | -------------------------------------------------- | ------------ |
| 브랜드 | `brandId` | 해당 브랜드의 상품만 조회, 없거나 삭제된 브랜드이면 빈 목록과 `last: true`를 반환한다. | `?brandId=7` |


#### 페이지


| 항목     | 동작                                                                                 |
| ------ | ---------------------------------------------------------------------------------- |
| 기본값    | `page=0`, `size=20` — 첫 페이지, 최대 20개                                                |
| 페이지 번호 | 0부터 시작 (`0`: 첫 페이지, `1`: 두 번째 페이지). 마지막 페이지를 넘으면 빈 목록과 `last: true`를 반환한다. |
| 페이지 크기 | `size`는 1~100                                                                      |


OFFSET 방식으로 앞의 `page × size`개를 건너뛰고 최대 `size`개를 가져온다.


| 요청 예시            | 정렬된 결과에서 조회할 구간 |
| ---------------- | --------------- |
| `page=0&size=20` | 1~20번째 상품       |
| `page=1&size=20` | 21~40번째 상품      |


#### 정렬

기본값은 `sort=latest`로, 상품 생성 시각의 최신순으로 조회한다.


| 정렬           | 기준         | 동점 기준      |
| ------------ | ---------- | ---------- |
| `latest`     | 생성 시각 내림차순 | 상품 ID 오름차순 |
| `price_asc`  | 가격 오름차순    | 상품 ID 오름차순 |
| `likes_desc` | 좋아요 수 내림차순 | 상품 ID 오름차순 |


### 응답

성공 시 `200 OK`를 반환한다.


| 필드                   | 설명              | 예시          |
| -------------------- | --------------- | ----------- |
| `meta.result`        | 처리 결과           | `"SUCCESS"` |
| `meta.errorCode`     | 오류 코드, 성공 시 없음  | `null`      |
| `meta.message`       | 오류 메시지, 성공 시 없음 | `null`      |
| `data.content`       | 현재 페이지의 상품 목록   | 아래 JSON 참고  |
| `data.page`          | 페이지 번호          | `0`         |
| `data.size`          | 요청한 페이지 크기      | `20`        |
| `data.last` | 다음 페이지가 없으면 `true`, 있으면 `false` | `true` |


`data.content`의 각 상품은 다음 필드를 포함한다.


| 필드           | 설명                               | 예시        |
| ------------ | -------------------------------- | --------- |
| `id`         | 상품 ID                            | `12`      |
| `name`       | 상품 이름                            | `"운동화"`   |
| `price`      | 상품 가격                            | `89000`   |
| `brand.id`   | 브랜드 ID                           | `2`       |
| `brand.name` | 브랜드 이름                           | `"브랜드 B"` |


### 오류


| 상황                                      | HTTP 상태 | 오류 코드                 |
| --------------------------------------- | ------- | --------------------- |
| 페이지·크기 범위 위반, 숫자 파라미터 형식 오류, 지원하지 않는 정렬 | `400`   | `INVALID_REQUEST`     |
| 사용자 헤더 누락·형식 오류·존재하지 않는 사용자             | `401`   | `USER_NOT_IDENTIFIED` |
| 처리되지 않은 서버 오류                           | `500`   | `INTERNAL_ERROR`      |




### 응답 예시

```json
{
  "meta": {
    "result": "SUCCESS",
    "errorCode": null,
    "message": null
  },
  "data": {
    "content": [
      {
        "id": 12,
        "name": "운동화",
        "price": 89000,
        "brand": {
          "id": 2,
          "name": "브랜드 B"
        }
      }
    ],
    "page": 0,
    "size": 20,
    "last": true
  }
}
```

### 마지막 페이지 판단

고객 상품 목록은 `totalElements`를 반환하지 않는다. `page * size` 위치에서 `size + 1`개까지 조회하고, 최대 `size`개만 반환한다. 추가 상품이 있으면 `last: false`, 없으면 `last: true`다. 정확히 `size`개만 남은 경우와 빈 목록도 `last: true`다. 필터·삭제 제외·정렬을 적용한 결과를 기준으로 판단한다.

### 좋아요 수·재고 분리 API

상품 목록·상세·내 좋아요 목록의 상품 정보는 `id`, `name`, `price`, `brand`만 반환한다. 좋아요 수와 품절 여부는 아래 API로 별도 조회한다.

| 요청 | 응답 `data` 예시 |
| --- | --- |
| `GET /api/v1/products/like-counts?ids=12,13` | `[{"productId":12,"likeCount":3},{"productId":13,"likeCount":0}]` |
| `GET /api/v1/products/stocks?ids=12,13` | `[{"productId":12,"soldOut":false},{"productId":13,"soldOut":true}]` |

두 API 모두 위와 같은 `meta`·`data` 응답 형식과 `X-USER-ID` 식별을 사용한다.

| 입력·상황 | 처리 |
| --- | --- |
| `ids` | 필수. 쉼표로 구분한 양수 Long ID 1~100개, 중복 제거 전 개수 기준 |
| 중복·입력 순서 | 중복 제거 후 상품 ID 오름차순 반환 |
| 없는 상품·삭제 상품·삭제 브랜드 소속 상품 | 결과에서 제외. 모두 제외되면 `200`, `data: []` |
| ids 누락·빈 값·형식 오류·0/음수·101개 이상 | `400 INVALID_REQUEST` |
| 사용자 헤더 누락·형식 오류·없는 사용자 | `401 USER_NOT_IDENTIFIED` |

프론트는 목록에서 받은 ID로 두 API를 호출하고 `productId`로 합성한다. 미수신 값을 좋아요 0개·재고 있음으로 가정하지 않는다. 내 좋아요 목록은 본인 확인을 유지하며, 페이지 정보도 기존 `totalElements` 계약을 유지한다.

### 캐시와 표시 갱신

캐시가 켜지면 저장마다 TTL **5분 ±30초**를 적용하며, hit로 만료 시간이 연장되지 않는다. 좋아요 수·좋아요순 순위는 만료까지 이전 값이 보일 수 있다. 상품·브랜드·재고 변경과 내 좋아요 목록 변경은 해당 DB revision으로 구분한다. 삭제·본인 확인은 표시 지연 허용 대상이 아니며 주문 판단은 원본 DB를 사용한다.

TTL은 저장된 캐시의 수명이며, 동시 변경·장애를 포함한 모든 요청의 최신성을 보장하는 전역 시간 상한이 아니다. 상세 계약은 [week2 API 계약](../week2/api-contract.md)을 따른다.


### 브랜드 필터 목록

`GET /api/v1/brands?page=0&size=100`을 기존 `X-USER-ID`로 호출한다. 응답 `data`는 `{content: [{id, name}], page, size, totalElements}`이며 삭제된 브랜드는 포함하지 않는다. size는 최대 100이므로 전체 검색용 목록은 다음 페이지를 이어 받아 합친다. 관리자 API·정적 브랜드 JSON에 의존하지 않는다.
