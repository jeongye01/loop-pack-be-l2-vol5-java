# 상품 100만 개 데이터 생성 계획

작성일: 2026-10-13

상태: CSV 생성·검증, EC2 적재·앱 연결 전환 완료. 상품 10만 개 후보안을 대체하는 새 데이터셋 목표다. 기존 CSV·DB·baseline 결과는 보존한다.

## 규모와 분포

| 항목 | 정확한 생성 건수 | 분포 목표 |
| --- | ---: | --- |
| 상품 | **1,000,000개** | 아래 브랜드 규모별로 배분 |
| 브랜드 | **1,000개** | 대형 100개에 상품 500,000개 · 중형 300개에 300,000개 · 소형 600개에 200,000개 |
| 사용자 | **240,000명** | 약 61%는 좋아요 0개 · 상위 20%가 전체 좋아요의 약 89% 생성 |
| 좋아요 | **690,000개** | 상품 상위 1%에 약 39% · 상위 10%에 약 84% 집중 |
| 재고 | **1,000,000개** | 상품마다 재고 행 하나 |

브랜드별 상품 수는 대형 각각 5,000개, 중형 각각 1,000개, 소형은 200개 브랜드에 각각 334개·400개 브랜드에 각각 333개를 배분한다. 브랜드 규모는 상품 수 기준이며 좋아요 인기도 순위와 같은 의미가 아니다.

## 좋아요 분포를 건수로 환산

분포 목표 비율은 원본 통계를 정수 퍼센트로 반올림한다. 원본 분석 문서와 JSON의 정밀한 수치는 보존한다.

점유율은 좋아요 개수 내림차순으로 정렬한 상품·사용자 기준이다. 상위 10% 상품에는 상위 1% 상품이 포함된다.

| 대상 | 대상 수 | 좋아요 목표 |
| --- | ---: | ---: |
| 좋아요 없는 상품 | 790,000개 (79%) | 0개 |
| 좋아요 있는 상품 | 210,000개 (21%) | 합계 690,000개 |
| 상위 1% 상품 | 10,000개 | 약 269,100개 (39%) |
| 상위 10% 상품 | 100,000개 | 약 579,600개 (84%) |
| 좋아요 없는 사용자 | 146,400명 (61%) | 0개 |
| 좋아요 있는 사용자 | 93,600명 (39%) | 합계 690,000개 |
| 상위 20% 사용자 | 48,000명 | 약 614,100개 (89%) |

총건수·0개 대상 수는 정확히 맞추고, 상위 점유율도 표의 정수 건수에 정확히 맞추며 오차는 0으로 검증한다.

상품당 임의의 200개 상한은 적용하지 않는다. 동일 사용자·상품 쌍은 한 번만 생성한다. 상품당 최대는 사용자 수 이하여야 하며, 이번에는 좋아요를 생성하는 사용자가 93,600명이므로 그 수를 넘을 수 없다. 사용자당 좋아요 수도 좋아요가 있는 상품 수를 넘을 수 없다.

## 통계 근거와 실험용 가정

이커머스의 인기 편중을 재현하기 위해, 소수에 활동이 집중되는 파레토 원리와 멱법칙의 관점을 참고한다. 실제 Taobao 데이터에서도 상위 10% 상품에 즐겨찾기의 약 84%가 집중됐다. 실험 데이터는 보편적인 80:20 비율을 강제하지 않고 이 관측 비율을 반영해 구성한다. 다만 해당 데이터가 멱법칙 분포에 적합한지는 검정하지 않았다.

- 상품·사용자·좋아요 비율과 편중의 근거는 [Taobao 즐겨찾기 분포 분석](references/taobao-fav-analysis.md)이다. 상품 4,161,138개·사용자 987,991명·고유 즐겨찾기 쌍 2,869,977개에서 상품 규모를 약 100만 개로 줄이고 사용자·좋아요 총량을 반올림했다.
- 위 분석을 정수 퍼센트로 반올림한 상품 0건 비율 79%, 상위 1%·10% 점유율 39%·84%, 사용자 0건 비율 61%, 상위 20% 점유율 89%를 목표로 삼는다.
- 브랜드 수와 대형·중형·소형 배분은 **실험용 가정**이다. Taobao에서 집계한 브랜드 통계가 아니다.
- 원본은 9일간 관측된 즐겨찾기 행동이다. 장기간 누적 좋아요나 국내 패션몰 전체의 분포를 재현한다고 주장하지 않는다. 원본의 전체 분포와 동일하거나 멱법칙에 적합하다고 주장하지 않는다.
- 사용자 지시에 따라 분포·생성 건수 외에는 기존 생성 방식을 유지한다. 가격 1~99,999,999원·재고 0~99,999,999개의 균등 난수, Datafaker 2.5.1 영어 이름, seed 42, 고정 시각 `2026-01-01 00:00:00.000000` UTC와 CSV 형식은 유지한다. 앞서 제안한 가격·재고 구간 비율은 적용하지 않는다.

구간 내부의 좋아요 수는 순위의 제곱근 역수 가중치로 배분하고 순위 구간이 뒤섞이지 않게 범위를 둔다. 상품 구간별 범위는 12~1,000 / 2~12 / 1~2개, 사용자 구간별 범위는 3~500 / 1~3개다. 이 구간 내부 모양은 합성 방식이며 원본에서 추정한 분포 모수가 아니다. 무작위로 섞은 ID에 목표 수를 할당하고, 남은 목표 수가 큰 사용자부터 연결해 중복 없이 양쪽 합계를 맞춘다.

## 생성과 검증

1. 고정 seed로 브랜드·사용자·상품·재고를 만들고, 상품별·사용자별 목표 좋아요 수를 배분한다.
2. 양쪽 목표 합계가 모두 690,000개인지 확인하고, 중복 없는 사용자·상품 관계로 연결한다. 두 분포를 동시에 만족시킬 수 있는지 확인하며, 맞지 않는 목표를 조용히 변경하지 않는다.
3. 실제 CSV를 다시 읽어 총건수, 이름 고유성·길이, 가격·재고 도메인 범위, 참조 누락, 좋아요 중복, 상품당 재고 하나를 검증한다. 브랜드별 상품 수와 좋아요 0개 대상 수도 확인한다.
4. 좋아요 상위 점유율·평균·중앙값·p95·최댓값을 집계해 목표와 비교하고, 생성 조건·체크섬과 함께 보관한다.

CSV 경로는 `docs/week4/seed-data/skewed-1m-v1/`, DB 이름은 `perf_skewed_1m_v1`로 둔다. 생성기·검증기는 기존 균등 버전과 새 편중 버전을 모두 지원한다.

같은 EC2 MySQL에 별도 DB로 적재하고 `ddl-auto=none`으로 실행한다. [기존 디스크 추정](references/ec2-disk-estimate.md)은 상품 10만 개 기준이므로 이 계획의 확정 용량으로 사용하지 않는다. 새 규모의 적재 전후 용량을 확인하고, 같은 코드로 타임아웃 5초의 baseline을 다시 측정한다.

## 적재 결과 (2026-10-13)

- 서울 EC2의 `perf_skewed_1m_v1`에 위 5개 테이블을 적재했다. 모든 필드의 행 체크섬·건수가 CSV와 일치했고 적재 경고는 0건이다. [적재 검증 보고서](load-reports/perf_skewed_1m_v1.json)
- CSV 5개는 총 261,768,009 bytes(약 249.6 MiB). 같은 seed로 재생성한 CSV의 체크섬이 모두 일치했다.
- DB EC2 루트 디스크 사용률은 27% → 32%, 사용량은 5,213,138,944 → 6,158,962,688 bytes다. 기존 DB, 새 DB, 전송한 CSV·압축 파일 등이 포함된 전체 파일시스템 사용량이며 새 DB 자체의 크기가 아니다.
- 앱의 연결 DB만 새 DB로 변경했다. 기존 `perf_uniform_10k_v1`과 연결 설정 백업은 보존했다. 앱 이미지·스키마·인덱스는 변경하지 않았다.
- 브랜드 7·가격 오름차순·첫 페이지 20개 응답의 모든 데이터 필드가 CSV 기대값과 일치했다. 해당 브랜드의 전체 상품 수는 5,000개다.
