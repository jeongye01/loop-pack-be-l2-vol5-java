# 상품 10만 개 적재 시 EC2 디스크 용량 추정

작성일·측정일: 2026-10-13

**기존 DB를 보존하고 상품 10만 개·좋아요 100만 개의 새 DB를 추가하면, 디스크 사용률은 약 28% 전후로 예상한다.** 현재 테이블 용량을 이용한 추정이며 새 데이터 적재 결과는 아니다.

## 현재 측정값

대상: 서울 DB EC2 `16.184.11.214`, MySQL 컨테이너 `week4-db-mysql-1`, DB `perf_uniform_10k_v1`.

| 디스크 항목 | 실제 값 |
| --- | ---: |
| 루트 파일시스템 전체 | 19,594,608,640 bytes (약 18.25 GiB) |
| 사용 중 | 5,213,110,272 bytes (약 4.86 GiB) |
| 사용 가능 | 14,364,721,152 bytes (약 13.38 GiB) |
| `df` 표시 사용률 | **27%** |

이전 baseline에서 관측한 25%와 이번 측정값은 시점이 다르다. 이번 추정은 27%를 기준으로 한다. 파일시스템 사용량에는 OS·Docker 이미지·DB·로그 등이 모두 포함되므로 상품 1만 개만의 용량으로 해석하지 않는다.

| 테이블 | 기존 적재 건수 | 데이터 + 인덱스 용량 |
| --- | ---: | ---: |
| `brand` | 100 | 32,768 bytes (0.03 MiB) |
| `users` | 10,000 | 507,904 bytes (0.48 MiB) |
| `product` | 10,000 | 3,178,496 bytes (3.03 MiB) |
| `stock` | 10,000 | 1,835,008 bytes (1.75 MiB) |
| `product_like` | 999,493 | 112,443,392 bytes (107.23 MiB) |

건수는 기존 적재 검증 기록 기준이다. 용량은 이번에 조회한 `information_schema.tables`의 `data_length + index_length`다. 함께 조회되는 InnoDB `table_rows`는 추정치이므로 정확한 건수로 사용하지 않았다.

## 10만 상품 시나리오

브랜드 100개·사용자 1만 명은 유지하고 상품·재고를 각각 10만 개, 좋아요를 100만 개로 설정한다. 좋아요는 현재와 거의 같은 건수로 계산한다.

| 경우 | 테이블 용량 증가 추정 | 파일시스템 사용률 예상 |
| --- | ---: | --- |
| 기존 DB를 교체 | 상품·재고 추가분 약 43 MiB | 약 27%대 |
| 기존 DB 보존 + 새 DB 추가 — 계획한 방식 | 새 DB 약 156 MiB | 약 28% 전후 |

계산: 상품·재고 현재 합계 약 4.78 MiB × 10 + 좋아요 약 107.23 MiB + 브랜드·사용자 약 0.52 MiB ≈ **156 MiB**.

현재 사용량에 새 DB 추정치를 더한 값은 전체 파일시스템의 약 27.4%다. `df`는 가용 공간을 기준으로 사용률을 계산하고 정수로 올림하므로, 여기서는 정수 표시 기준 약 28%로 제시한다.

## 추정의 한계와 확인 사항

- 같은 스키마·인덱스와 비슷한 행 크기를 가정한 선형 추정이다. 상품명 길이, 인덱스 페이지 사용량, 통계 오차에 따라 실제 크기는 달라진다.
- 적재 중 binlog·임시 공간·로그 증가와 서버에 복사할 CSV 파일은 위 테이블 용량에 포함하지 않았다. 적재 중 최대 사용률을 보장하는 값은 아니다.
- 기존 DB 교체도 삭제한 공간이 파일시스템에 반환되는지에 따라 결과가 달라진다. 실제 계획은 기존 DB를 보존하는 방식이다.
- 적재 전후 `df`와 테이블 용량을 다시 확인한다. **저장 공간 여유는 조회 성능을 보장하지 않는다.** 새 데이터로 baseline을 다시 측정한다.

## 측정 방법

DB EC2에서 파일시스템을 확인했다.

```bash
df -B1 /
```

MySQL에서 데이터·인덱스 용량을 읽었다. 데이터 변경이나 통계 갱신은 하지 않았다.

```sql
SELECT table_name, table_rows, data_length, index_length
FROM information_schema.tables
WHERE table_schema = 'perf_uniform_10k_v1'
ORDER BY data_length + index_length DESC;
```
